## 学んだこと
- `Array(要素数).fill(埋める値)`で、配列の中身をすべて指定した値で埋めることができる。
- 字数を指定する問題も一部あり、昨日の`padStart`の復習にもなった。

```js
const [n, a, b] = [3, "A", "B"];
const pair = `(${a}, ${b})`;

Array(n).fill(pair); //=> ["(A, B)", "(A, B)", "(A, B)"]
```

```js
const [h, w, a, b] = lines[0].split(" ").map(Number);
const pair = `(${String(a).padStart(9, " ")}, ${String(b).padStart(9, " ")})`

const row = Array(w).fill(pair).join(" | ");
const separator = Array(row.length).fill("=").join("");

for (let i = 1; i <= h; i++) {
    
    console.log(row);
    
    if (i !== h) {
        console.log(separator);
    }
    
}
```

- 変数名のAI添削  
  💡「処理内容」ではなく「それが何であるか(名詞)」で考えると自然になりやすい。
  - `setAB` → `pair`：`(A, B)`という文字列。`setAB`だと動詞っぽく何かをsetしているのかと思えてしまう。値の中身を表す名詞に変更。
  - `sentence` → `row`：「文章」というより「**1行分のデータ**」という性質が強い。`sentence`だと大げさで意味もズレる。
  - `line` → `separator`：`line`だと「1行のテキスト」という意味で使われることも多く、「行と行を区切る線」という意図とはズレる。

## 気づき・詰まったこと
- 変数名の指定がいまいち苦手である。
- それが何であるかを指すという、本質的な思考が必要で、単に「区切り線」と翻訳をかけた結果（line）をそのまま書けば良いということではない。
- これは慣れる、場数を踏む、たくさん変数を考えるしかないように思える。
