## 学んだこと
- **配列操作メソッドの仕様理解と実践**
  - 例：`const birds = ["buncho", "hato", "suzume"];`

| メソッド/プロパティ | 操作内容 | 戻り値 | 破壊性 |
|---|---|---|---|
| `push` | 末尾に要素を追加 | 追加後の配列の `length`（要素数）<br>例：`4`（引数なしの場合は`3`） | 破壊的（✅） |
| `pop` | 末尾の要素を削除 | 削除された要素<br>例：`"suzume"` | 破壊的（✅） |
| `unshift` | 先頭に要素を追加 | 追加後の配列の `length`（要素数）<br>例：`4`（引数なしの場合は`3`） | 破壊的（✅） |
| `shift` | 先頭の要素を削除 | 削除された要素<br>例：`"buncho"` | 破壊的（✅） |
| `splice(start, deleteCount)` | 指定位置から**指定個数**の要素を削除・追加・置換 | 取り除いた要素（配列）<br>例：`(0, 2)` → `["buncho", "hato"]`<br>`birds`は `["suzume"]`となる。削除しない時は `[]`が返る。` | 破壊的（✅） |
| `slice(start, end)` | 指定範囲（`end`の手前まで）を複製 | 複製された要素（配列）<br>例：`(0, 2)` → `["buncho", "hato"]`<br>※元の配列は変更なし | 非破壊（❌） |
| `indexOf` | 検索値と一致する最初のインデックスを返す | 該当インデックス（存在しない場合は`-1`） | 非破壊（❌） |
| `flat` | 多次元配列のネストを平坦化（デフォルトは深度1） | ネストが解消された配列 | 非破壊（❌） |
| `split` | 文字列を指定パターンで分割 | 分割された要素が格納された配列 | 非破壊（❌） |

- **多次元配列（ネスト構造）の平坦化**
  - 配列内に配列が含まれる構造において、`.indexOf()` はネスト内部の要素まで直接検索できない（`-1` が返る）。
  - `.flat(深度)` を用いて階層を平坦化してから、`.indexOf()` や `.length` などのメソッド・プロパティを結合させて、動的に要素を特定するアプローチを学んだ。

## 気づき・詰まったこと
- **`console.log()`内でのメソッド実行**
  - `console.log(birds.pop());`と書いた場合、「popした状態を表示するだけ」だと思っていたが、その後の`console.log(birds);`で配列が書き換わったことを確認。
  - 実際は、画面に出力する前の段階で、まず引数内の式（`birds.pop()`）が評価（実行）されている。
    そのため、ログ出力の時点でpopは実行されており、元の配列が書き換わっている。
- **配列への要素追加時の挙動**
  - 要素が3つの配列に対してインデックス100番に値を追加（`birds[100] = "tsubame"`）。
    - 予想：自動で最後尾に追加される（インデックス3に`tsubame`が入る、要素は4）。
    - 結果：間の97個は`empty`（空スロット）として埋まる（インデックス100に`tsubame`が入る、要素は101）。
      `['buncho', 'hato', 'suzume', empty × 97, 'tsubame']`
      - `empty`のインデックスを参照すると`[]`ではなく`undefined`が返る。
- **`splice`の返り値**
  - `splice`の返り値は「取り除いた要素（配列）」であり、操作後の配列ではない。
  - 第3引数なし（削除のみ）でも、第3引数あり（置換）でも、返り値は変わらず「取り除いた要素」。
  - 置換後の配列を返したい場合は、`splice`後に別途配列を`return`する必要がある。
- **`indexOf`は入れ子の中を探せない**
  - 入れ子構造の配列に対して`indexOf`を使っても`-1`が返った。`flat()`でフラットにしてから使う必要がある。
- **応用の面白さを実感**
  - `length`をインデックスとして活用したり、`split`と`slice`を組み合わせて文字列を配列に変える関数を実践。
