# 2026年05月17日

## 学んだこと
- **関数の実践**
  [前日](2026-05-16.md)に学んだ関数の基礎をもとに、実践的な課題をクリア。引数・処理・returnの一連の流れを定着させた。
- **テンプレートリテラル**
  - バッククォート（\`）を使用するとコードがスッキリし、改行もシンプル。可読性アップ。
    - `文鳥は${kawaii}そして${supercute}です。`
    - "文鳥は" + kawaii + "そして" + supercute + "です。"
  - バッククォートは、`Shift` + `@`で入力。
- **実務におけるコードの品質**
  - **名前の重複回避**  
    `function type(type)`のように、関数名と引数名を同じにすると可読性が低下する。  
    引数には value や data など、中身の具体像を表す名前を付けるべき。
  - **脱・ローマ字命名**  
    `teihen`や`takasa`といったローマ字命名は避ける。  
    `base`や`height`といった世界標準の英語での命名を徹底する。
  - **関数の外の変数を直接書き換えるリスクとクロージャ**  
    関数の中から外の変数を直接書き換える仕様は、実務ではバグの温床となるため避けた方が良い。  
    解決策としてクロージャを学んだ。

## 気づき・検証したこと
- **テンプレートリテラルでの改行コントロール**
  - コードの見栄えを崩さず、出力だけを改行したい場合は、文中に直接改行コード`\n`を入れると良い。  
  例：`1行目\n2行目`
  - コード内で改行したいけれども出力を1行におさめたい場合は、バックスラッシュを使用することで改行をエスケープすることができる。  
    例：`1行目A\`  
    　　`1行目B`

- **クロージャの仕組み**
  - `=`（代入）の右側にお尻のカッコ () をつけて関数を実行すると、外側の皮を剥いて「戻り値（中の関数）」だけが左側の変数に移植される。
  - なぜ呼び出すたびに初期化（let = 0）されないのか？
    外側の関数（`let`のある大枠の部屋）の処理は、**()で呼び出した時の1回のみ**実行されて、その後は消滅するため。
  - 実行時には初期化のコード自体はすでに消滅しているが、変数の箱だけはメモリに残り続け、中の関数はその箱への「住所」を持ち続けているため、呼び出されるたびに同じ箱を読み書きする。
    これがリセットされずに変数の中身が引き継がれる理由。
